## 行为分析

- Stage1 确实执行了真实训练：完成 7 个 GRPO 步，每步均写入 rollout 文件，并在训练结束时保存 actor checkpoint。
- Stage1 reward 行为显示策略逐渐收敛到恰好一次搜索：到 step 7 时，`reward_extra/search_count/mean=1.0`、`second_plus_search_count=0`、`paid_search_count=0`。
- Stage2 在重设计后按预期运行：PhaseA 先生成 actor 轨迹，PhaseB 使用离线 batch teacher 生成，并将失败/证据不足样本过滤，而非使整个数据集失败。
- Stage2 数据质量满足 Stage3 需求：保留 252 个 pair，无 teacher 错误、无超时、无非法 pair schema。
- Stage3 使用 VERL DPO，TP=1，8 路数据并行。这符合小模型约束，并避免对 Qwen3-1.7B 使用 tensor parallelism。
- 评测确认最终 agent 可靠完成 AIR 搜索流程：每个评测样本均成功回答，且均恰好发起一次搜索。
- 与基础模型相比，SPAD Stage3 最终模型的 EM 基本持平，F1 仅小幅上升：EM 0.1543 -> 0.1543，F1 0.2512 -> 0.2519。
- SPAD Stage1 单独评测低于基础模型：EM 0.1486，F1 0.2460。DPO 阶段恢复了这一下降，但在 500 个训练样本下未形成明确增益。
- Search-R1 original `global_step_7` 是本次对比中最强的一行：EM 0.1714，F1 0.2665，增益主要来自 hotpotqa、musique、nq 和 triviaqa。
- 主要局限是搜索深度：每个 query 稳定地只搜索一次，但对多跳数据集较弱，这与 bamboogle、hotpotqa 和 musique 上的低 EM/F1 一致。下一次运行应在 reward 或数据策略中显式鼓励证据不足时有效的第二步搜索，否则模型将继续收敛到一次搜索。

### Stage1 历史 Reward 分支分布

Stage1 的 7 个 rollout 文件共包含 3,584 条轨迹。下表使用该历史运行当时的 reward 设置，其中 `bad_stop.penalty=-0.35`；不代表后续修改后的默认配置。

| Reward 分支 | 数量 | 占比 |
| --- | ---: | ---: |
| 无搜索执行记录 | 3 | 0.08% |
| 格式非法或未合法结束 | 964 | 26.9% |
| Bad stop，reward `-0.35` | 1,231 | 34.3% |
| Teacher 判定答案受证据支持 | 1,384 | 38.6% |
| Teacher 输出格式错误 | 2 | 0.06% |
| **总计** | **3,584** | **100.0%** |

结果解读：

- 历史 reward 日志中的 `no_search_evidence` 表示 `tool_call_details` 中没有字典记录，因此更准确的含义是“无搜索执行记录”。它不表示已执行搜索但返回了无关或空文档。
- 只有 3 条轨迹没有搜索记录。主要失败是搜索后的 bad stop，以及格式非法或未完成轨迹，而非没有调用搜索。
- Reward 为 `-0.5` 的 967 条轨迹由 3 条无搜索记录轨迹和 964 条格式非法或未合法结束轨迹组成。
- Teacher 在 2,617 条轨迹上被调用：1,384 条为 supported answer，1,231 条为 bad stop，2 条为 teacher 格式失败，占全部 rollout 的 73.0%。
- 因此 bad stop 是一个主要优化分支：actor 已经搜索并合法停止，但在耗尽 5 次搜索预算前，teacher 判定已累积证据不足或模糊。
