## 结论

- 真正的修复是 `offline_vllm_batch`，而非调优 HTTP inflight。HTTP `max_inflight_per_teacher=32` 虽可缩短 wall time，但仍是按单样本调度请求。
- 在 200 query smoke 中，`offline_batch_no_eager` 使用 4 个 TP=2 worker，每个 worker 执行一次 `LLM.generate(prompts)` batch，活跃期平均 AICore 达 40.9%，最大值达 87%。
- 离线 batch 的总耗时仍为 345.6 秒，因为 no-eager 冷启动需要编译和捕获图。每个 shard 对约 49--50 个 prompt 的实际 batch 生成延迟约为 80--84 秒，该成本可在 5100 query 的正式 Stage2 中摊薄。
- 数据质量仍然有效：198/198 个符合条件的 teacher 调用全部完成，无 teacher 错误、无超时、无 schema 非法 pair；保留数 92 处于 HTTP 变体的随机波动范围内。
