## Teacher Prompt Template 与三类完整样例

### 三类并非三套 Template

`supported_answer`、`insufficient_evidence` 和 `ambiguous_evidence` 并不走三套
teacher prompt。Stage1 对每个合法停止的搜索轨迹都调用同一个
`build_teacher_messages(question, evidence_steps, include_status=True)`；三类是
teacher 在相同 messages 下生成的 `<status>`，而不是代码按类别选择的 template。
System prompt 定义位于
`agentic_iter_rag/agent_training/spad/prompts.py:18-30`，user message builder 位于
`agentic_iter_rag/agent_training/spad/prompts.py:38-74`，调用点在
`agentic_iter_rag/agent_training/spad/rewards/search_policy_teacher_reward.py:273-281`。

本次运行的 request 配置为 `temperature=0.0`、`top_p=1.0`、
`max_tokens=512`、`enable_thinking=false`，每轮最多向 teacher 展示 5 篇文档。
共享的 system template 和 user layout 如下：

```text
SYSTEM

Do not use markdown or numbered lists. Use only the evidence. The status must be exactly one of supported_answer, insufficient_evidence, ambiguous_evidence. Use supported_answer only when the evidence supports a single short answer. Use insufficient_evidence when the evidence is missing necessary facts. Use ambiguous_evidence when the evidence supports multiple incompatible answers. The reason must briefly state the supporting evidence, or state what evidence is missing and why the current evidence is insufficient. The answer must be only the final short answer span, usually one person, date, place, number, or title. Keep names, dates, places, titles, and numbers exactly as written in the evidence when possible. If the evidence is insufficient or ambiguous, answer exactly 证据不足无法作答.

            [1] {title_1}
               {contents_1}
            ...
            [5] {title_5}

   Now output the final result directly. Do not analyze the instruction. Do not repeat rules. Begin with <reason>.
```

Stage1 rollout 没有持久化 HTTP `messages` payload 或服务端 chat-template
token 序列。以下三条完整 prompt 使用历史 500-run 保存的原始问题和 tool response，
通过**调整后的当前** `build_teacher_messages` 确定性重新渲染；除 vLLM 在 messages
之外加上的模型包装符外，没有省略隐藏指令或证据文档。下方 teacher XML 仍是历史
500-run 在旧排版下的原始输出，本次只修改 prompt 结构，未重新调用 teacher 模型，
因此不能把 XML 当成新排版的消融结果。

## 对 Stage1 Reward 的影响

Teacher 契约在 `agentic_iter_rag/agent_training/spad/prompts.py:22-25` 中明确将 `ambiguous_evidence` 定义为存在多个互不兼容答案的证据。当搜索次数尚未达到预算时，reward 将 `ambiguous_evidence` 和 `insufficient_evidence` 均视为失败的过早停止（`agentic_iter_rag/agent_training/spad/reward.py:151-183`）。对于 `supported_answer`，则使用 teacher 答案与 gold 的 F1 计分（`agentic_iter_rag/agent_training/spad/reward.py:186-190`）。

本次运行的 rollout 汇总结果清楚展示了这种不对称：

| Teacher 结果 | 行数 | 典型观测分数 |
| --- | ---: | ---: |
| `insufficient_evidence` 或 `ambiguous_evidence` | 1,231 | -0.35 |
| `supported_answer` 且 teacher F1 = 0 | 375 | 平均 -0.0316 |

因此，对一条本可回答的单次搜索轨迹给出错误 `ambiguous_evidence` 标签，会注入强负 reward，并告诉策略不要停止。错误的 `supported_answer` 即使答案错误，其负值也小得多。人工审计显示两类失败都存在，但错误歧义分支尤其严重，因为抽样的 ambiguous 标签中有 6/10 根本不应进入该分支。

这并不证明 teacher 噪声单独导致了 Stage1 评测下降：Stage1 训练子集与 Search-R1 子集不同，且 Stage1 不训练 answer body。但它确实证明，当前 reward 对 teacher 的一部分模糊判断给出了符号错误或过于严厉的 credit assignment，且该子集不可忽略。

## 后续建议

1. 在估计全局比例前，使用更大的固定样本审计：每个状态抽取 100 行，按问题去重，并由两名人员独立标注。分别报告 `S/I/A` 一致率、答案正确性以及问题/数据缺陷。不要将 gold 字符串是否出现当作人工标签。

2. 收紧 teacher 契约。要求它对答案中的每个关系输出一个引用段落 ID。明确说明 `ambiguous_evidence` 必须存在针对**同一谓词**的两个答案，而非不同事件、不同型号或相关技术术语。增加 `claimed` 对比 `carried out`、电视剧对比书籍、宽泛日期对比精确日期的示例。

3. 为 teacher `supported_answer` 结果增加低成本 verifier。它应检查问题中的命名实体是否出现在引用段落中，并请第二个 judge 判断引用句子是否表达原始谓词。这可在推理时不使用 gold label 的前提下，定向解决 Tyler/Tim 和 Sookie/Rene 类错误支持。

4. 不要立即对所有 `ambiguous_evidence` 结果给出相同的终局惩罚。对歧义标签，允许一次 query rewrite 或使用第二个独立 teacher，然后再应用 bad-stop penalty。这比“仅因较弱的状态标签声称答案有歧义，就奖励额外搜索”更合理。

5. 训练期间将数据缺陷与策略失败分开。标记“检索证据与 gold 直接冲突”或“所需桥接缺失”的问题。将它们从 Stage1 teacher reward 中排除，或使用中性 reward；否则有效的证据对齐行为会被惩罚。

6. 将 `supported_answer` 且 teacher F1=0 视为一类独立的审计桶。本次运行中共有 375 行（占 supported 行的 27.1%）。它既包含真实的 teacher 答案错误，也包含 gold 粒度问题，因此在修改惩罚前应先抽样；不应自动将它视为证据不足。
