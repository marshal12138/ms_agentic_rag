# AIR Reranker Prompt、Parser 和 Reward 详细设计

更新日期：2026-07-03

## 1. 目标

这篇文档拆解三个强相关模块：

- reranker prompt 怎么写。
- reranker 输出怎么解析。
- reranker reward 怎么算。

这三件事必须放在一起设计，因为 reward 的第一步就是格式校验，而格式校验完全依赖 prompt 约束和 parser。

第一版目标很明确：

```text
reranker 输入 question + sub_query + 50 docs
reranker 输出 <reason> 和完整 50 排序
格式错误直接 -0.5
格式正确才触发 frozen agent continuation
```

## 2. 非目标

第一版不做：

- 不用静态 qrels 计算 NDCG/MRR 作为主 reward。
- 不接 LLM-as-judge。
- 不允许只输出 top5。
- 不允许输出 doc_id 替代候选 index。
- 不对格式错误做自动修复后继续 rollout。

格式错误就是训练信号的一部分，直接惩罚。

## 3. Prompt 模板

新增模板版本：

```text
air_rerank_tags_v1_full50
```

它可以基于现有 `AIR_RERANK_PROMPT_WITH_INITIAL_QUERY` 改造。

核心变化：

- 原来要求输出 EXACTLY M passages。
- 现在要求输出 ALL 50 passages。
- `<rerank>` 中必须包含 50 个 distinct index。

prompt 结构：

```text
You are a professional document reranker specialized in multi-step search and reasoning tasks.

You will be given:
- An Initial Query: the user's ultimate question and final goal.
- A Current Sub-Query: a focused query generated by the search agent.
- A list of 50 candidate passages retrieved by the retriever.

Your goal:
Rank ALL 50 passages by usefulness for the current step.

Primary principle:
Ranking is based on the Current Sub-Query, but the Sub-Query must be interpreted under the Initial Query.

Output format:
<reason> ... </reason>
<rerank> [i] > [j] > ... </rerank>
```

明确要求：

- `<reason>` 写 5 到 8 句短解释。
- `<reason>` 里不要写 passage index。
- `<rerank>` 只能写 `[1]` 到 `[50]`。
- `<rerank>` 必须正好 50 个 index。
- 不能重复。
- 不能带分数、逗号、JSON 或额外文本。

## 4. Prompt 渲染接口

建议在现有文件里扩展：

```text
AgenticIterRag/agentic_iter_rag/llm_reranker/format.py
```

新增函数：

```text
render_air_rerank_full50_prompt(
    initial_query: str,
    sub_query: str,
    docs: list[dict],
    max_doc_chars: int,
) -> tuple[list[dict[str, str]], dict[str, str]]
```

返回：

- VERL chat messages。
- `candidate_index_to_doc_id`。

实现要求：

- `docs` 数量必须是 50，除非配置明确允许少于 50 的 debug mode。
- 每篇 doc 用 `[idx]` 编号，从 1 开始。
- 仍然保留 title 和 text。
- text 优先读 `text`，兼容读 `contents`。

代码注释要求：

- 在 full50 prompt 函数前写中文注释，说明它和现有 topM prompt 的区别。
- 在 doc 字段选择处写中文注释，说明为什么同时兼容 `text` 和 `contents`。

## 5. Parser 设计

建议新增：

```text
AgenticIterRag/agentic_iter_rag/reranker_training/parser.py
```

核心接口：

```text
parse_rerank_response(text: str, expected_n: int = 50) -> RerankParseResult
```

返回结构：

```text
RerankParseResult:
  valid: bool
  reason: str | None
  ranked_indices: list[int]
  error_code: str | None
  error_message: str | None
```

错误码建议：

- `missing_reason_tag`
- `missing_rerank_tag`
- `tag_order_error`
- `empty_reason`
- `empty_rerank`
- `invalid_index_token`
- `index_out_of_range`
- `duplicated_index`
- `wrong_index_count`

解析规则：

1. 检查 `<reason>` 和 `</reason>`。
2. 检查 `<rerank>` 和 `</rerank>`。
3. 检查 tag 顺序。
4. 抽取 `<rerank>` 内容。
5. 用正则抽 `[数字]`。
6. 确保没有其他非法 token。
7. 校验数量等于 expected_n。
8. 校验 index 在 `[1, expected_n]`。
9. 校验无重复。

如果 valid，返回 ranked indices。

如果 invalid，返回错误码，不抛异常。reward 层会根据 invalid 直接给 penalty。

代码注释要求：

- parser 分支必须有中文注释，尤其是“为什么不自动补齐缺失 index”。
- 错误码定义处要有中文注释，方便后续指标统计。

## 6. Reward 总流程

reward 入口逻辑：

```text
parse reranker response
if invalid:
    return format_penalty

top5_docs = ranked_docs[:5]
new_answer = continuation_rollout(messages_before_tool_response, top5_docs)
answer_score = answer_reward_fn(new_answer, gold_answers)

if strategy == answer_reward:
    return answer_score

if strategy == delta_answer_reward:
    return answer_score - baseline_reward
```

格式错误时不能触发 continuation。原因：

- 格式错误代表 reranker action 不可执行。
- 如果继续 rollout，就必须猜测排序或 fallback，这会把错误动作变成其他动作。
- 这样 reward 就不再对应模型真实输出。

所以 `-0.5` 是直接动作级惩罚。

## 7. Reward 模块接口

建议新增：

```text
AgenticIterRag/agentic_iter_rag/reranker_training/reward.py
```

核心接口：

```text
compute_reranker_reward(
    reranker_output_text: str,
    sample_extra_info: dict,
    config: dict,
    continuation_runner: ContinuationRunner,
) -> dict
```

返回：

```json
{
  "score": 0.7,
  "valid": true,
  "format_valid": true,
  "format_error_code": null,
  "answer_score": 0.7,
  "baseline_reward": 0.5,
  "reward_strategy": "answer_reward",
  "ranked_doc_ids": ["doc1", "doc2"],
  "visible_doc_ids": ["doc1", "doc2", "doc3", "doc4", "doc5"],
  "final_answer": "new answer",
  "continuation_status": "answered"
}
```

格式错返回：

```json
{
  "score": -0.5,
  "valid": false,
  "format_valid": false,
  "format_error_code": "wrong_index_count",
  "answer_score": null,
  "baseline_reward": 0.5,
  "reward_strategy": "answer_reward",
  "continuation_status": "skipped_format_error"
}
```

代码注释要求：

- `format_valid=false` 分支必须写中文注释，说明不触发 continuation。
- `delta_answer_reward` 分支必须写中文注释，说明 baseline 的含义。
- reward extra info 写入处要注释这些字段用于训练日志和问题排查。

## 8. Reward Strategy

### answer_reward

默认策略。

```text
score = answer_score
```

优点：

- 训练信号直接。
- 方差相对小。
- 早期更稳定。

### delta_answer_reward

可选策略。

```text
score = answer_score - baseline_reward
```

优点：

- 更强调 reranker 相对原 retriever top5 的增益。

风险：

- reward 可能为负。
- 如果 baseline 本身高分，reranker 很难拿正分。
- 对 baseline_reward 的质量更敏感。

第一版默认不启用。

## 9. Reward Function 加载

配置：

```yaml
reranker_training:
  reward:
    answer_reward_function:
      path: AgenticIterRag/rewards/search_qa_f1_with_format_penalty.py
      name: search_qa_f1_penalty_compute_score
```

加载规则：

- path 支持 repo 相对路径和绝对路径。
- name 必须存在。
- 函数签名沿用现有 reward 约定。
- 加载失败时训练入口直接失败。

不要在 reward 模块里 hardcode 某个 reward function。

## 10. GRPO Reward 写入

对 VERL batch，最终 reward 应写到 reranker response 的最后一个有效 token。

extra info 需要保留：

- `final_score`
- `format_valid`
- `format_error_code`
- `answer_score`
- `baseline_reward`
- `reward_strategy`
- `visible_doc_ids`
- `final_answer`
- `continuation_status`

这些字段用于：

- debug 格式错误。
- 分析 reranker 是否真的提升 answer。
- 分析 top5 变化。
- 分析 reward 分布。

## 11. 错误处理

直接 penalty：

- parser invalid。

直接失败：

- reward function 加载失败。
- `delta_answer_reward` 但 baseline 缺失。
- `candidate_index_to_doc_id` 缺失。
- ranked index 找不到 doc。

可配置失败或 penalty：

- continuation agent 请求失败。
- retriever 请求失败。
- continuation 超时。

第一版建议 continuation infra error 直接失败，不转成模型 penalty。原因是这是系统错误，不是 reranker action 错误。

## 12. 测试计划

### 12.1 Parser 正向测试

输入完整 50 index。

期望：

- `valid=true`
- `ranked_indices` 长度 50
- 顺序保持一致

### 12.2 Parser 负向测试

覆盖：

- 缺 reason
- 缺 rerank
- 重复 index
- 少于 50 个 index
- 多于 50 个 index
- index 0
- index 51
- 带逗号或 JSON

期望：

- `valid=false`
- 错误码准确

### 12.3 Format Penalty 测试

格式错误时：

- reward = -0.5
- continuation runner 没有被调用
- `continuation_status=skipped_format_error`

### 12.4 answer_reward 测试

mock continuation 返回 answer。

mock answer reward 返回 0.7。

期望：

- final score = 0.7

### 12.5 delta_answer_reward 测试

baseline = 0.4。

new reward = 0.7。

期望：

- final score = 0.3

### 12.6 注释验收

人工检查：

- parser 复杂分支有中文注释。
- reward 关键策略有中文注释。
- format penalty 不触发 continuation 的原因写清楚。
