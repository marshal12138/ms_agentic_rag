# SPAD Teacher PE 代码结构介绍

## 1. 目录职责

本目录是 GLM-4.7-Flash teacher 的独立 prompt engineering 工作区，包含冻结数据、prompt 变体、
推理 runner、评分、服务脚本、测试和实验报告。除生产 registry 集成外，消融代码和结论均在本目录内。

## 2. 数据链路

### `build_manual_judgments_237.py`

从 500-run 的原始 rollout JSONL 重建 237 条审计索引，应用已记录的人工纠错并生成
`manual_judgments_237.tsv`。脚本校验三类数量和一致/不一致统计，避免手工表格漂移。

### `build_benchmark.py`

依据 TSV 中的源文件和行号恢复 Original question、gold、每轮 sub-query 与 top-5 passage，生成：

- `benchmark_237.jsonl`：runner 的唯一固定输入。
- `benchmark_237.manifest.json`：样本数、label/split 统计和 SHA256。

切分按规范化问题分组，防止同一问题同时出现在 dev 与 holdout。

## 3. Prompt 层

### `prompt_variants.py`

定义 `PromptVariant` registry。每个变体包含：

- `name`：稳定实验 ID。
- `system_prompt`：teacher 指令。
- `include_gold`：是否向 user prompt 加入 reference gold。
- `family`：instruction、gold、layout、meta 等实验族。
- `description`：实验意图。
- `layout`：v1/v2/evidence-only/question-tail 等 user prompt builder。

`build_messages()` 是统一入口。当前维持策略是
`baseline_question_tail_evidence_only_v2`：不展示 sub_query，保留完整 passage，并在尾部重复问题。

生产代码位于 `AgenticIterRag/agentic_iter_rag/agent_training/spad/prompts.py`。该文件已具有 v1/v2
registry 和版本解析；持续计划中的 v3 尚未注册为生产默认值。

## 4. 推理与评分

### `run_ablation.py`

完整 XML teacher runner，主要流程为：

1. 从冻结 benchmark 选择 all/dev/holdout。
2. 通过 prompt registry 构建 messages。
3. 把请求分配到一个或多个 OpenAI-compatible vLLM endpoint。
4. 普通调试可按完整 payload SHA256 缓存；正式消融用 `--disable-cache` 强制请求模型，同时保存
   endpoint、耗时、usage 和 raw content。
5. 解析 `<reason><status><answer>`，生成逐样本 `predictions.jsonl`。
6. 计算三分类、I 二分类、S/A 容忍混淆、parse rate 和输出长度。
7. 输出 `metrics.json`、`errors.tsv`、`report.md`、`run.json`、`variant.json` 和 system prompt snapshot。

关键参数包括 `--variant`、`--split`、`--endpoints`、`--max-workers`、
`--inflight-per-endpoint`、`--max-tokens`、`--enable-thinking` 和 `--seed`。
独立重复还必须传 `--disable-cache`，并在完成后检查 `run.json.cache_hits=0`；共享 response cache
的复放结果不算一次实验。vLLM prefix KV cache 不复放历史输出，和 runner response cache 是两层机制。

### `run_binary_gate.py`

研究用 one-token I/non-I runner。它通过 vLLM
`structured_outputs.choice=[I,N]` 强制生成一个 token并保存 I/N logprob，在 dev 上选阈值、在 holdout
上冻结评估。该方案速度快，但准确率不够，当前不作为生产候选。

### `evaluate_ensemble.py`

读取多个已落盘 predictions，用冻结的 I vote threshold 评估多 prompt 投票，并计算串行/理想并行成本。
它不重新调用模型。投票仅保留为研究对照。

## 5. 服务管理

- `launch_teacher_replicas.sh`：启动 4 个 GLM-4.7-Flash vLLM replica，每个 TP=2，占用 8 张 NPU。
- `status_teacher_replicas.sh`：检查容器运行与 `/v1/models` ready 状态。
- `stop_teacher_replicas.sh`：停止并删除本实验启动的四个容器。
- `runtime/replicas.tsv`：端口、卡号与容器名的运行清单。

安全并行原则：每个 replica 的所有实验进程合计并发不超过 16。策略之间可以并行，策略本身是否多调用
必须在成本报告中明确。

## 6. 报告生成

- `build_results_index.py` 扫描 `results/**/metrics.json`，生成 `RESULTS_INDEX.md`。
- `build_stability_report.py` 校验 Top 5 三重复均为 `cache_hits=0`，汇总准确率、耗时和 token，并附上
  此前累计稳定性，生成 `REPLICA_STABILITY.md`。
- `ABLATION_HISTORY.md` 记录实验假设、每十次复盘、淘汰原因和当前选择。
- `持续消融计划.md` 记录冻结结论、生产集成、新数据验证和停止规则。

`results/_invalid_data_leakage/` 中的实验违反 few-shot 数据隔离；`results/_invalid_cached_replay/`
中的实验复放了历史 response。二者只能用于审计，任何选择脚本和报告都必须标记为 INVALID。

## 7. 测试

`test_teacher_pe.py` 当前覆盖：

- benchmark 数量和 split。
- XML parser 的完整、status 截止和异常输出。
- I precision/recall 与 S/A 容忍统计。
- baseline/gold/instruction-only user 输入约束。

运行：

```bash
python -m unittest -v test_teacher_pe.py
python -m py_compile prompt_variants.py run_ablation.py run_binary_gate.py
```

生产 v3 集成时还需增加逐字符 message snapshot 和 prompt-version propagation 测试。

## 8. 结果目录约定

每个 `results/<experiment>/` 是不可变实验快照。不要覆盖已有目录；正式消融使用新 ID 和
`--disable-cache`。
核心文件：

```text
predictions.jsonl   逐样本输入、原始输出、解析结果、耗时
metrics.json        aggregate 指标
errors.tsv          人工标签与模型不一致项
report.md           单次实验 Markdown 摘要
run.json            请求参数、endpoint、墙钟、缓存信息
variant.json        prompt 名称、family、layout、hash
system_prompt.txt   实际 system prompt 快照
```
